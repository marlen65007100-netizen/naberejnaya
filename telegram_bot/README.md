# НАБЕРЕЖНАЯ — оптовый Telegram-бот

Для @naberejnayamarketbot. Клиент выбирает раздел, товар и целое количество блоков, проверяет корзину, вводит имя, телефон и точку доставки, затем подтверждает отправку. Владелец получает заказ с суммой, блоками, штуками и ссылкой на локацию. Кнопки «Принят» и «Доставлен» доступны только владельцу.

В каталоге 27 баночных позиций из присланного прайса, цены уже с НДС. Трёхлитровые банки — по 4 в блоке; томатная паста 430 г — по 10; аджика и перец 320 г — по 18; остальные — по 8. Весовые товары отсутствуют, поскольку этот бот принимает заказы только блоками. Цена блока рассчитывается как цена банки × размер блока.

Минимальный заказ — 500 000 сум. Доставка по Ташкенту включена, оплата наличными. До 12:00 по Ташкенту доставка в этот день, после — на следующий. Время доставки 08:00–18:00.

## Запуск на Render

Код должен находиться в GitHub-репозитории `marlen65007100-netizen/naberejnaya`. Сначала проверьте, что папка `telegram_bot` действительно загружена. Подключённый GitHub-аккаунт сам по себе не подтверждает наличие прав на запись.

Для постоянной работы нужен один платный Web Service с диском. Free-план не подходит для этого варианта: он засыпает и не поддерживает постоянный диск. Выбор платного плана нужно согласовать до создания сервиса.

### Запуск через готовую конфигурацию

В корне репозитория есть `render.yaml`: один Web Service `naberejnaya-marketbot`, план `0.5c-512mb` (бывший Starter), регион Frankfurt, один экземпляр и постоянный диск 1 ГБ в `/var/data`. Перед созданием проверьте и подтвердите регулярную стоимость в Render.

1. Открыть [готовую настройку Render](https://dashboard.render.com/blueprint/new?repo=https://github.com/marlen65007100-netizen/naberejnaya), выбрать `My Workspace` и ветку `main`.
2. В поле `BOT_TOKEN` вставить токен из BotFather. Он сохраняется только в закрытых настройках Render.
3. Проверить тариф и создать Blueprint. Render сам выполнит 24 теста и запустит бота.
4. После статуса Live открыть @naberejnayamarketbot в Telegram, нажать Start и отправить `/id`.
5. Добавить в настройках сервиса Environment переменную `ADMIN_CHAT_ID` с полученным числом и сохранить с перезапуском. До этого приём заказов отключён; просмотр каталога и команда `/id` доступны.
6. Проверить `/health`: `running: true, orders_configured: true`, затем провести реальный пробный заказ и убедиться, что он пришёл владельцу.

`ADMIN_CHAT_ID` не задаётся в Blueprint: первый запуск использует значение `0`, а последующие обновления сохраняют добавленный вручную ID владельца.

### Ручная настройка

1. Создать Web Service из репозитория в согласованном пространстве `My Workspace`.
2. Runtime: Python. Build Command: `python -m compileall -q telegram_bot`. Start Command: `python telegram_bot/bot.py`. Health Check Path: `/health`. Запускать ровно один экземпляр.
3. Подключить диск 1 ГБ с Mount Path `/var/data`.
4. В Environment добавить `BOT_TOKEN` из BotFather и `BOT_DB_PATH=/var/data/marketbot.sqlite3`. Токен вводится только в закрытые настройки, никогда в GitHub.
5. Для первого запуска временно оставить `ADMIN_CHAT_ID=0`. Владелец открывает бота, нажимает Start, отправляет `/id` и получает свой числовой Telegram ID. Приём заказов до настройки получателя отключён.
6. Указать полученный ID как `ADMIN_CHAT_ID`, сохранить с перезапуском. На старте бот проверяет свой username и личный чат получателя.
7. Убедиться, что Render показывает Live, `/health` возвращает `running: true, orders_configured: true`; затем вручную проверить полный заказ из Telegram до сообщения владельцу. Локальные тесты не подтверждают доставку реального сообщения.

Если уже настроен webhook, процесс остановится, сохранив его. Миграцию на polling нужно отдельно подтвердить; удалять ожидающие обновления не нужно.

## Данные и повторная отправка

Корзины, этапы оформления, заказы и очередь сообщений хранятся в SQLite на диске. Изменение корзины отменяет старое подтверждение. Повторное нажатие «Отправить» не создаёт новый заказ. Заказ сохраняется до отправки менеджеру; клиент получает подтверждение передачи только после успешного ответа Telegram.

При сетевом тайм-ауте Telegram мог принять сообщение, хотя ответ не дошёл. Повторная попытка может дать второе сообщение с тем же номером заказа. Одинаковый номер означает один заказ. В API Telegram нет ключа идемпотентности для `sendMessage`.

В базе находятся персональные данные клиентов. Не загружайте базу, `.env` и токен в GitHub. Сервис не раздаёт файлы по HTTP: публичен только статус здоровья. Логи не содержат тела заказов или Telegram URL с токеном.

## Обновление цен

Править `catalog.json`: `unit_price` — цена банки с НДС, `units_per_block` — количество банок в блоке. Идентификаторы товаров сохранять. Если прайс изменился во время оформления, клиент должен заново проверить сумму и подтвердить заказ.

Фотографии подключены из существующего каталога для совпадающих позиций. Для товара без подходящего фото показывается текстовая карточка. При сбое загрузки фотографии бот переходит к текстовой карточке.

Проверка без токена и без отправки сообщений: `python -m unittest discover -s telegram_bot/tests -v` из корня репозитория.

Официальные справки: [Telegram Bot API](https://core.telegram.org/bots/api), [Render Web Services](https://render.com/docs/web-services), [постоянные диски](https://render.com/docs/disks), [переменные окружения](https://render.com/docs/configure-environment-variables).
